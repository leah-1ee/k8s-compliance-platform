# Demo Scenario

이 문서는 KubeOwl의 최종 발표 및 기능 검증용 엔드투엔드 시나리오를 정리한다.

## 목적

- 공개 랜딩 페이지부터 사용자 콘솔, 관리자 콘솔, 공개 문서까지 한 흐름으로 검증한다.
- 정책 생성, kubectl 적용 안내, 런타임 분석, 관리자 감사 확인, Grafana 접근을 순서대로 보여준다.
- 데모 중에는 `0.2.13` 이미지 기준과 현재 배포 흐름이 일치해야 한다.

## 사전 조건

- 브라우저에서 `/`, `/docs`, `/ui`, `/admin` 경로에 접근할 수 있어야 한다.
- AI 서버는 `docker.io/leeon3345/compliance-ai-server:0.2.13` 기준으로 배포되어 있어야 한다.
- 로그인 계정과 관리자 토큰이 준비되어 있어야 한다.
- 런타임 이벤트를 보여주려면 Falco와 Falco Sidekick이 동작하는 클러스터가 필요하다.

## 시나리오

### 1. 공개 랜딩 확인

1. 브라우저에서 사이트 루트(`/`)를 연다.
2. 랜딩의 버튼 계층과 소개 문구가 읽히는지 확인한다.
3. `Sign in`을 눌러 로그인 흐름으로 진입한다.

기대 결과:
- 랜딩 화면이 바로 보인다.
- 로그인 진입 버튼이 명확하다.
- 비로그인 상태에서도 공개 문구가 무너지지 않는다.

### 2. 사용자 콘솔 진입

1. 로그인 후 `/ui`로 이동한다.
2. Policy Generator에서 자연어 정책을 입력하고 YAML 결과를 확인한다.
3. 생성된 정책의 validate/mutation 구분과 안내 문구를 확인한다.

기대 결과:
- 정책 YAML이 생성된다.
- public 정책 생성 흐름이 유지된다.
- 최신 태그 금지, non-root, 허용 레지스트리, host namespace 금지, mutation 자동 주입이 설명된다.

### 3. 클러스터 적용 안내

1. Policy Apply 또는 kubectl 안내 섹션을 연다.
2. Assign / mutation 정책에 대한 적용 가이드와 troubleshooting 흐름을 보여준다.
3. 필요하면 클러스터 소유권과 적용 상태 안내를 확인한다.

기대 결과:
- 사용자가 직접 실행할 `kubectl` 명령이 분명히 보인다.
- AI 서버가 클러스터에 직접 적용하지 않는다는 점이 안내된다.
- fallback 상태가 있을 때도 거짓 성공으로 보이지 않는다.

### 4. 런타임 분석

1. Runtime Event 목록에서 이벤트를 연다.
2. Violation Detail에서 rule, namespace, pod, container, cause, severity explanation, recommended fix를 확인한다.
3. AI Report에서 분석 결과를 확인한다.

기대 결과:
- 이벤트 상세가 실제 컨텍스트를 포함한다.
- 요약이 아니라 원인과 수정 방향이 함께 보인다.
- 필요한 경우 kubectl manifest 안내가 유지된다.

### 5. 관리자 콘솔

1. `/admin`으로 이동한다.
2. 감사 로그, 사용자/클러스터 상태, 토큰 관리, 복구/비활성화 흐름을 확인한다.
3. 필요하면 Grafana 관리자 진입점도 확인한다.

기대 결과:
- 관리자 전용 화면이 정상 표시된다.
- 감사 로그와 운영 정보가 분리되어 보인다.
- 관리자 토큰이 필요한 경로와 일반 사용자 경로가 구분된다.

### 6. 공개 문서

1. 로그아웃 상태 또는 별도 브라우저에서 `/docs`를 연다.
2. 문서가 로그인 없이 열리는지 확인한다.
3. 문서 안에서 테스트/가이드/기능 설명이 현재 구현과 맞는지 확인한다.

기대 결과:
- `/docs`는 공개 접근 가능하다.
- 문서가 현재 기능 설명과 어긋나지 않는다.

### 7. Grafana 확인

1. 사용자 콘솔 또는 관리자 흐름에서 Grafana 진입을 확인한다.
2. 대시보드의 사용자 스코프 메트릭이 보이는지 확인한다.
3. `No data`가 아니라 실제 값이 표시되는지 확인한다.

기대 결과:
- Grafana 접근이 끊기지 않는다.
- 메트릭이 사용자 범위로 보인다.
- Live/ws 잡음이나 공개 경로 오류가 데모 흐름을 방해하지 않는다.

## 데모 종료 체크

- 브라우저 새로고침 후 `/`, `/docs`, `/ui`, `/admin`이 모두 정상 동작하는지 다시 확인한다.
- 현재 배포 이미지 태그가 `0.2.13`인지 확인한다.
- 마지막으로 테스트 캡처가 필요하면 해당 화면을 저장한다.
